# Updating your portfolio

## Quick map

| What to change | File |
| --- | --- |
| Project cards, filters, images, links, homepage selection | data/projects.ts |
| ML hub model/method cards | data/ml-implementations.ts |
| Experience, skills, biography, education, certificate URLs | data/knowledge.ts |
| Resume PDF | public/resume.pdf |
| New interactive algorithm logic | lib/your-algorithm.ts |
| New interactive controls and charts | components/your-demo.tsx |
| New case-study page | app/projects/ml-from-scratch/your-slug/page.tsx |

## Add a project — one content file

Add this object inside `projects` in `data/projects.ts`. Replace the example with real work:

```ts
{
  id: "customer-churn", // Unique, stable identifier
  name: "Customer Churn Prediction",
  category: "ML Projects",
  featured: false,
  description: "Describe the problem and what you built.",
  technologies: ["Python", "Scikit-learn"],
  features: ["Explain your approach.", "Describe your evaluation and results."],
  repository: "https://github.com/your-name/your-repo",
  image: "/projects/customer-churn.png",
  imageLabel: "Customer churn results",
  // demo: "https://your-live-app.com",
  // caseStudy: "/projects/your-existing-case-study",
  // status: "Ongoing",
},
```

Save the actual screenshot as `public/projects/customer-churn.png`. Omit `image` when there is no screenshot; the decorative bars appear automatically. Local image paths need no import. Do not use a dashboard screenshot URL as a live application.

Categories: Data Analytics, Data Analysis, Excel Analysis, ML Projects, Pure Python Projects, AI & DL Projects. These are defined at the top of the same file; adding another category there creates its filter.

Set `featured: true` on your four chosen projects. The first four flagged entries in array order become the homepage and Top 4 selection. Unflag a previous project when replacing it. Project titles can change without editing another component. The chatbot receives the same project data automatically.

Optional actions: `repository` gives Code; `caseStudy` opens an existing internal page; otherwise `demo` opens a live app; otherwise an image gives a preview button. A new page is not generated by setting its URL.

## Add an ML algorithm to the hub

Add an entry to `mlImplementations` in `data/ml-implementations.ts`:

```ts
{
  id: "logistic-regression",
  title: "Logistic Regression",
  family: "Supervised learning / Classification",
  description: "Explain what you implemented and what the reader can explore.",
  topics: ["Python", "NumPy", "Classification"],
  code: "https://github.com/your-name/your-repo/tree/main/logistic_regression",
  // caseStudy: "/projects/ml-from-scratch/logistic-regression",
},
```

This creates the card and includes it in search and sorting. Add only completed implementations. Leave `caseStudy` out until its page exists; adding a data entry does NOT implement an interactive demo.

### Build the interactive demo

1. Implement the actual mathematics as pure functions in `lib/logistic-regression.ts`. Write numerical tests in `tests/` for known results and edge cases.
2. Create `components/logistic-regression-demo.tsx` with `"use client"`, state, controls, and charts. Use bounded runs, pause/reset, labeled controls, reproducible synthetic data, and cleanup for timers. Explain what the chart measures and avoid presenting synthetic results as real evaluation.
3. Create `app/projects/ml-from-scratch/logistic-regression/page.tsx`:

```tsx
import Link from "next/link";
import { Page } from "@/components/portfolio";
import { LogisticRegressionDemo } from "@/components/logistic-regression-demo";

export const metadata = { title: "Logistic Regression | Rudrapratap Sarma" };
export default function CaseStudy() {
  return <Page eyebrow="ML FROM SCRATCH" title="Logistic Regression" intro="Explain the learning objective.">
    <Link href="/projects/ml-from-scratch">All implementations</Link>
    <LogisticRegressionDemo />
  </Page>;
}
```

4. Set `caseStudy` in the hub entry to the new route. Test it before publishing.

Use `closed-form-demo.tsx`, `gradient-demo.tsx`, and `lib/gradient-descent.ts` as structural examples, but implement the correct mathematics for each new algorithm. Check mobile and both themes. Update the ML project's description/features in `data/projects.ts` and the hub roadmap when the completed scope changes.

## Add experience

In `data/knowledge.ts`, add a real entry at the top of `experience` (newest first):

```ts
{
  id: "company-ml-intern-2027",
  company: "Company Name",
  role: "Machine Learning Intern",
  type: "Internship",
  duration: "Jan 2027 - Present",
  location: "Bengaluru · Hybrid",
  responsibilities: [
    "Describe your work and tools.",
    "Include a supported achievement or result."
  ],
},
```

Use a different `id` for every role, including multiple roles at one company. `type` can be Internship, Full-time, Part-time, or Project-based training. Location examples: `Remote`, `Bengaluru · On-site`, `Bengaluru · Hybrid`; use `""` to hide it. The timeline, homepage experience count, and chatbot read this data. Remove test/placeholder roles before publishing. Keep biography, availability, career goals, and resume current too.

## Certificates and other content

Edit `certifications` in `data/knowledge.ts`: title, provider, and a public HTTPS `url`. An empty URL disables the certificate button. Replace `public/resume.pdf` to update the download. Do not put API keys into content files or Git; configure secrets in Vercel Environment Variables and local `.env.local`.

## Check and publish

Run from the folder containing package.json:

```bash
npm run dev
# Check the changed page in the browser, including mobile and both themes.
npm run lint
npm test
npm run build
```

A production build regenerates Next.js route types after switching branches. Stop the dev server before building; restart it afterwards.

For a reviewed update on main:

```bash
git status
git add data/projects.ts
# Add any other files you intentionally changed, including screenshots.
git commit -m "Update portfolio projects"
git push origin main
```

Vercel deploys pushes to main. For experiments, start from a clean checkout and create a feature branch instead, push it, and review a pull request before merging. Do not force-push to resolve conflicts.
